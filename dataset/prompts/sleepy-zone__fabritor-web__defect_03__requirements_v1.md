Acceptance checklist:
## Public acceptance checklist

### R1 - Workspace Startup and Viewport Fitting
When the user opens fabritor, the end of the loading state must reveal the top toolbar, the six-tab left panel, a centered white artboard, and the Canvas settings on the right at the same time. The blank artboard must have artwork dimensions of 1242 × 1660 pixels, with gray workspace margin visible around it. When the user changes the browser window's width or height or repeatedly resizes the viewport, the central canvas must refit while keeping the artboard centered; existing objects' artboard coordinates, dimensions, angles, and layer order must remain unchanged, and repeated resizing must not cause a single subsequent action on the current canvas to be handled more than once.

### R2 - Feature Tabs and Content Creation
When the user clicks the Design, Text, Image, Material, Paint, and App tabs in turn, the left panel must switch to the corresponding content without removing any objects already on the artboard. After the user clicks Text Box, an image option, or a line, geometric-shape, or Hand-Drawn thumbnail, a new object must be created at the center of the artboard, become the current selection, and show settings appropriate to its type on the right. Dragging after entering the Paint tab must draw a continuous stroke; on release, the stroke must become an independent object, and leaving the Paint tab must restore selection mode. A DEMO must be loadable when the layer list is empty, and content already added to the artboard must remain unchanged after returning from the QRCode or Emoji subpage.

### R3 - Canvas Zoom and Pan Mode
When the user scrolls the mouse wheel over the central workspace, the viewport must zoom continuously around the workspace center and remain within 0.01× to 20×. After the user clicks the Pan button in the top toolbar, objects must temporarily become unselectable, the pointer must use a grab cursor, and pressing and moving must pan only the viewing area. After the user exits Pan mode, objects must become selectable again. Continuing to zoom with the mouse wheel in a panned viewport must not change the artboard's artwork dimensions or object coordinates, and after repeatedly entering and exiting the mode, the current mode, pointer style, and object selectability must always correspond.

### R4 - Object Selection and Transform Controls
After the user clicks an ordinary object, a #FF2222 red selection border and red circular control handles must appear. As the user drags a corner handle, an available edge-midpoint handle, or the top rotation handle, the object's dimensions or angle must update continuously; a live angle must be shown during rotation, and on release the selection controls, property values, and layer thumbnail must all reflect the completed state. For applicable objects, the top and bottom midpoint handles must be hidden when the width is below 100 pixels, and the left and right midpoint handles must be hidden when the height is below 40 pixels; the handles must return when the object is enlarged again. After rotation, scaling, and reselection, the selection controls must remain aligned with the object's current outline.

### R5 - Properties and Common Operations
When the user selects the artboard, text, an image, a shape, a line, a paint stroke, Hand-Drawn content, or a group from the canvas or layer list, the right panel's title, field values, and type-specific tools must immediately switch to the current selection. Changes to the font, fill, stroke, filter, opacity, dimensions, or position must appear on the canvas at the same time. After the user locks an object, it must no longer be draggable or scalable; unlocking it must restore those controls. After Create a copy, Delete, Flip X or Flip Y on an image, or any of the seven artboard alignment operations, the selection state, position fields, layer list, and history must all reflect the same result.

### R6 - Layer Order and Group Management
When the user clicks a thumbnail in the Design tab, the corresponding canvas object must be selected and the current list item must be marked with a red border. After an object is added, deleted, modified, or moved in the stacking order, the thumbnail list must promptly update from topmost to bottommost, and the occlusion of overlapping objects must match the list. After the user right-clicks and uses Move Up, Move to Top, Move Down, Move to Bottom, Copy, Paste, or Delete, the menu must close and the resulting state must be visible. After a multi-selection is grouped, it must be transformable as a unit; after it is ungrouped, its members must become independently selectable again while retaining their individual styles and relative positions.

### R7 - Brushes and App Content
After the user selects Pencil or Marker Pen in the Paint tab and adjusts the color, line width, line cap, and shadow, pressing and moving the pointer must continuously create a stroke with the current settings. On release, the entire stroke must become an object that can be selected, moved, and deleted, and Stop Drawing must toggle back and forth between drawing and selection states. After the user enters the QRCode or Emoji subpage, configures content, and adds it to the artboard, the new content must become an independent object. Returning to the App list, switching to another tab, or entering the subpage again must not clear existing objects or the current artboard state.

### R8 - History and Clear Confirmation
After the user completes an add, delete, move, scale, rotation, property adjustment, grouping, or layer-order operation, Undo must become available and restore object states in reverse operation order; after an undo, Redo must reapply them in their original order. Starting a new edit from an undone position must replace the subsequent records with a new edit chain. History must retain at most 100 entries. When the user clicks Clear, a confirmation dialog must appear first; canceling must leave the artwork and history unchanged, while confirming must clear ordinary objects and history together, return the layer list to its empty state, and disable Undo and Redo at the same time.

### R9 - Template Loading and Artwork Export
When the user clicks Load and selects a previously exported JSON file, a loading state must be shown while the file is read. When loading finishes, the artboard dimensions, object coordinates, styles, and layer order must be established from the file, and history must be reset from the loaded result; canceling file selection must preserve the current artwork. When the user selects JPG, PNG, SVG, JSON, or Copy to Clipboard from the Export menu, the output must contain only the artwork's artboard and objects, without the gray workspace or editing overlays. After export finishes, the current zoom, selection, viewport position, and state needed to continue editing must remain unchanged.

### R10 - Keyboard Shortcuts and Editing State
After the user selects an ordinary object, Ctrl/Cmd+C, Ctrl/Cmd+V, Delete/Backspace, Ctrl/Cmd+Z, and Ctrl/Cmd+Shift+Z must perform copy, paste, delete, undo, and redo, respectively. Each press of an arrow key must move the object one pixel in the corresponding artboard direction, with the canvas, layer list, and position fields updating together. Once text enters content-editing mode, the arrow keys must move only the text cursor and must not move the text box; nudging must resume after returning to object-selection mode. Consecutive shortcuts, menu operations, and right-panel operations must share the same selection and history state.

### R11 - Text Box Layout and Visible Bounds
When the user creates a Text Box from the Text tab and drags its left or right width handle, the red selection border, handle positions, text-alignment area, and available width on each line must change together. Short text must be laid out across the full visible box according to the current left, center, or right alignment. When the user enters longer text or continues changing the font, font size, character spacing, or line height, the text must wrap by character upon reaching the visible boundary, the line count and text height must be recalculated, the layout width must always equal the current text-box width, and the selection border must enclose the resulting content.

### R12 - Consistent Object Dragging at Non-Default Zoom
After the user changes the editor canvas to a non-default zoom level and drags any selected object, the object body, selection boundary, corner handles, and side handles must always use the same current position, and their screen displacement must remain synchronized with the pointer. As the drag distance grows, no layer may gradually lag behind or lead, and the object and its boundary must not show two different positions. On pointer release, the object must stop directly at the release position without passing beyond the endpoint and rebounding or jumping from a delayed preview to its true position. Final coordinates, history, undo and redo, the boundary shown when the object is selected again, and the view after returning to default zoom must all refer to the same endpoint.
