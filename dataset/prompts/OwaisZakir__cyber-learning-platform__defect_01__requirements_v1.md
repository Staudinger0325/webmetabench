Acceptance checklist:
## Public acceptance checklist

### R1 - Shared Framework and Responsive Navigation
When the user starts at Home and clicks Modules, Paths, Courses, Quiz, Certs, Trainer, and FAQ in sequence, the fixed header retains the shield brand link, the link for the exact current page switches to a cyan highlight, the main content always remains above the scanline layer and dynamic canvas, and the matching footer links lead to the same pages. After the user narrows the window and clicks the menu button, the horizontal navigation collapses into a vertical menu, which closes when the user selects a destination or clicks the button again; the brand shield, the page's first heading, and the primary action buttons remain visible and operable in the current layout.

### R2 - Home Entry Points and Scroll Narrative
After opening Home, the user sees “Zero → Hero Cybersecurity,” the terminal-style course summary, Explore Curriculum, and View Career Paths; clicking the two entry points opens the module catalog and the career paths, respectively. As the user continues scrolling, the feature cards, Starting Point cards, differentiator cards, and final action section fade in while moving upward in the order in which they enter the viewport. The security icons in the first screen continuously float and rotate slightly at different rhythms, while the bottom arrow oscillates to prompt downward scrolling; when the user scrolls back or repeatedly hovers, completed reveal sequences do not flash repeatedly, and card-link destinations do not change with the visual emphasis.

### R3 - Module Search and Difficulty Filtering
As the user continuously enters a title or description fragment in the Modules search field, the module cards narrow in real time using a case-insensitive match against the current input. When the user then selects one of beginner, intermediate, or advanced, the search and difficulty conditions are intersected; clicking the currently selected difficulty again clears that condition, and deleting the search text restores the list according to any difficulty filter that remains. Each result card uses the current course data to show its module number, title, summary, duration, level, and tools preview and opens the corresponding detail page. When nothing matches, only the no-results message is shown; whenever either condition changes, the list is regenerated from the current data.

### R4 - Module Details and Content Tabs
After entering a valid module from the catalog, the user can switch among Objectives, Lessons, Labs, Tools, and Assessment; the current panel shows that module's objectives, lesson-by-lesson text and notices, hands-on tasks, tool tags, deliverables, and Instructor Notes, respectively. Clicking a lesson completion icon changes only that lesson's completion record and does not change the completion button for the whole module. When the user clicks Previous Module, Next Module, or Back to Modules, the destination, module badge, title, and content update together, and only a direction that actually exists remains available at a course boundary; a module number with no match returns to Modules without showing content left over from the previous module.

### R5 - Learning Records and Progress Restoration
After the user clicks Mark as Complete on a detail page, the button changes to Completed!, and clicking it again undoes the completion. When the user returns to Modules or re-enters the catalog from the application entry point, the module cards, Your Progress, the Completed and Remaining summaries, the progress fill, and the checklist are restored from the same locally saved learning record; before that record has loaded, the page does not first show a panel that conflicts with the saved state. When at least one module is complete, the user can click Reset to return the progress panel, the module and lesson completion sets, and the recent-visit record to their initial state and hide Reset. If the saved record cannot be parsed, browsing the catalog and module details continues with empty progress instead of being blocked.

### R6 - Continuous Cyber Background Response
While remaining on any page and moving the pointer slowly, the cyan matrix grid on the bottommost canvas drifts continuously along both the horizontal and vertical axes according to the pointer position, while the velocity directions of nearby particles change at the same time; depth scaling, connections between nearby particles, and the cyan, purple, and green glowing orbs continue evolving at their own rhythms. When pointer movement stops, the grid retains the phase corresponding to the most recent position. After the user changes pages, goes back, and repeatedly resizes the window, the background covers the current viewport and only one set of the grid, particles, connections, and glowing orbs responds; the canvas does not take over foreground clicking, typing, or scrolling, and the motion does not stack after repeated navigation.

### R7 - Branching Quiz and Progress Transitions
When the user clicks an option in Quiz to proceed to a later question, the current question card, question number, percentage, and fill bar first fade out together with the old quiz node's content while moving upward; only after the old state has fully exited do the next question and its corresponding progress fade in together. Throughout the continuous transition, the question text, options, and progress visible on the screen always refer to the same quiz node. Clicking an option that directly produces a recommendation, Go Back, or Start Over preserves the same state boundary: the result card appears only after the current question and progress have exited together, Go Back returns only to the immediately preceding history node, and Start Over clears the result, color, and history and restores the first question.

### R8 - Path, Course, and Resource Relationships
While browsing Paths, each path card shows the description, skills, associated modules, certification preparation, and career roles for Red Team, Blue Team, Purple Team, Cloud Security, or GRC. Clicking a module badge or Start This Path opens the corresponding module in the current catalog, and hovering over a card only strengthens that path's theme color. As the user continues to Courses, Certs, Resources, and Trainer, the course packages, assessment types, certification levels, tool categories, delivery formats, and trainer-development entry points remain browsable in their fixed information hierarchy; internal action links retain their defined destinations, and course mappings match the data on the current page.

### R9 - FAQ Search and Expanded State
After the user enters a term in Search FAQ, the page matches categories, questions, and answers at the same time and reorganizes the current matches under their original categories. Clicking an FAQ rotates its arrow and expands the answer; clicking it again collapses it, and selecting a different FAQ leaves only the current item expanded. When the query matches nothing, the no-results message and Clear Search are shown, and clicking Clear Search restores all categories. As the user repeatedly edits the query, expands an item, and then clears the input, the list always corresponds to the current text, and the contact-support card remains after the FAQ area.

### R10 - Login Modal and Role Permissions
When a signed-out user clicks Login, the backdrop modal shows an email field, Student, Teacher, and Admin role options, a submit button for the current role, and Cancel. Clicking a blank area of the backdrop or Cancel closes the modal, while clicking inside the form allows editing to continue. After a valid email is submitted, the header shows the email-prefix name, the corresponding USER, TEACHER, or ADMIN badge, and the account menu; Logout restores the public state. After Teacher and Admin users sign in, Teaching is shown; only Admin sees Admin, and Admin also has the Teaching entry. Other roles that directly enter a restricted page see a permission explanation and a Back to Home action, with the same permission result in the desktop and mobile menus.

### R11 - Teaching Area and Administration Actions
After a user with teaching access enters Teaching and switches among Modules, Tracks, Resources, and Community, the current tab shows only its corresponding content. In Modules, clicking a different teaching card changes the title, description, and lesson list below to the selected module; moving the pointer within a card produces a 3D tilt, and the card returns to its front-facing orientation when the pointer leaves. When an Admin user enters a name or email in Users, selects a role, opens the details, and grants access, revokes access, or deletes the user, the modal shows the action appropriate to the current role, and after the action the list and the groups in Access use the updated user state. Switching to Activity or Settings does not alter learning records.

### R12 - Loading, Resizing, and Unknown Addresses
As the user resizes the window between desktop and narrow-screen widths, the Home action buttons and primary cards reduce from multiple columns to fewer columns, tags wrap according to the available width, and the dynamic canvas immediately adopts the current viewport size and extends the grid. After repeated resizing or opening and closing the menu and modal, the current page still contains only one operable copy of its content. While waiting for a delayed page, the user sees a centered spinner; before the dynamic canvas is ready, the user first sees a solid dark background. At an unknown address, the user can return to Home or the previous page, and entering a module number with no match returns to Modules; after loading completes, no heading or panel from the previous page remains.
