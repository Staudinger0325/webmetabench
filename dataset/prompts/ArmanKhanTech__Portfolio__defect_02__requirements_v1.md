Acceptance checklist:
## Public acceptance checklist

### R1 - Home Loading Overlay and Ready State
When a user first enters Home, the welcome loading overlay must cover the fixed 3D scene and show the resource-preparation process. The main heading, action links, and navigation must not become operable floating content before the scene is ready. Once the resources are ready, the welcome overlay must disappear, and the greeting, role introduction, Hire Me, Résumé, social links, and bottom-right audio control must all become visible and usable at the same time. If the resources cannot be retrieved successfully, the wait must still end, with the Home information and navigation remaining available to browse.

### R2 - Site Navigation and Narrow-Screen Menu
When the user selects Home, About, Experience, Projects, Services, or Contact from the top navigation marked with AK, the corresponding content page must open with a title, content layer, and dynamic background that match that section. Content from the previous page must not continue to cover the new page. On a narrow viewport, expanding the menu must provide access to the same set of destinations. After the user selects a destination or closes the menu again, the menu must be dismissed and the main content must return to a fully readable state without covering links, forms, or the scrollable area.

### R3 - Home Content and Background Layering
After Home finishes loading, the name, role, Hire Me, Résumé, social links, and top navigation must remain on a distinct, recognizable information layer while the sky terrain scene fills the viewport beneath them and remains visible. When the user scrolls the information layer, moves the pointer, or uses the audio control, the text must not be covered by the 3D canvas, and the scene must not intercept the action links. After the user returns to Home, both layers must be re-established with the same front-to-back order and operable relationship. Whenever the background is not being held, the foreground must remain at fully readable opacity so that a user returning from another section can immediately recognize and use the Home action links.

### R4 - About Background Response Across Content
As the user moves the pointer on the About page, the orange nodes and connecting lines in the dark background must respond to its current position with a continuous, subtle disturbance. As the pointer travels from an empty area of the page into a Skills icon card, moves between cards, and then enters an Education timeline card, the background response must follow one uninterrupted trajectory. The content cards must remain scrollable and readable. After the pointer leaves a card or the user scrolls to later content, the network must neither freeze nor jump back to an earlier position, and touch devices must retain the corresponding page-level response.

### R5 - Skill and Education Content Pairing
As the user scrolls the About page, the About Me introduction, Skills grid, and Education timeline must appear in that order. Each skill entry must display the icon and name for that same skill together, and every education card must keep its icon, title, date, and bullet points associated with the same entry. After the viewport width changes, the grid column count and timeline layout may reflow, but skill names must not become separated from their icons, education content must not be lost, and the translucent cards and background network must continue to keep the text readable.

### R6 - Home Scene Dragging and Post-Release Motion
When the user presses and drags horizontally or vertically on the sky terrain background on desktop Home, the 3D scene must rotate continuously from its current orientation, while vertical tilt remains within a limited range suitable for viewing. During the drag, the overlaid introduction text must fade out while the navigation remains fixed in the foreground. When the user releases the pointer or moves it out of the background, the text layer must return and the scene must resume its slow autonomous rotation instead of remaining at the final dragged orientation. A subsequent drag must continue responding from the scene's moving orientation without a jump. Brief clicks, successive drags, and repeated drag-and-release cycles must all follow the same state transition, and the scene must not lose its autonomous motion after one drag has been completed.

### R7 - Browsing Experience, Projects, and Services
After entering Experience, Projects, and Services respectively, the user must be able to browse the complete content through the corresponding bird background, project cards with images, and graphical service entries. Experience cards must be organized as a timeline, while each project card must keep its image, name, description, technology tags, and associated link within the same project. When the user scrolls, hovers over a card, or selects an associated link, the background must not cover the main content, and the card feedback and link purpose must remain clear. A narrow-screen reflow must retain the content, order, and action links of every entry.

### R8 - Contact Form and Result Messages
After reaching Contact through Hire Me or an action link on a content page, the user must be able to enter a name, email address, and message and submit them. While submission is in progress, the button and message states must reflect the current processing state and prevent repeated clicks from submitting the same content more than once. Once sending is complete, an inline message must present the result and allow the user to continue editing and submit again. A success indication must not appear while the service has not yet returned a result or when sending cannot be completed. The planet and star-field background must remain beneath the content without preventing form input.

### R9 - Persistence of Audio Playback State
When the user activates the bottom-right audio control, the piano background music must start and the control must change to indicate Pause. Activating it again must pause the current audio and restore the Play indication, with the graphic state matching what the user actually hears. After the user chooses play or pause, that choice must persist while the user navigates between sections, opens the menu, drags the Home background, or scrolls any content page. If the browser does not permit autoplay, the control must still provide a usable way for the user to start playback manually. Loading, pausing, and resuming must not produce overlapping audio, and repeated toggling must always leave the same single track in its currently selected playback state.

### R10 - Page Re-entry and Resource Restoration
As the user moves back and forth between sections, resizes the window, or lets the page temporarily lose focus and then returns, each page's canvas, node-and-line network, birds, stars, or planet background must realign with the current viewport and content container, while the navigation and scrollable content remain accessible. After a page has been left, its former background must not remain over the new page, and duplicated animations or unresponsive pointer interactions must not remain. When the user returns to a previous section, models, images, and icons that are already ready must be restored promptly, while preserving the correct order of the loading, content, and interaction layers.

### R11 - Experience Flock Pointer Response
When the user sweeps the pointer quickly across the orange-to-red faceted bird flock in Experience, nearby birds must receive a brief, weak repulsive disturbance. When the pointer moves slowly within the same area, or pauses there briefly while continuing to produce input, the repulsive effect must accumulate with each input, causing local displacement, gaps, and flock rearrangement to continue increasing over the course of the influence. This continuous animation state must neither saturate immediately at a uniform magnitude on the first approach nor ignore later input in the same area. After the pointer moves away, the flock must continue flying according to separation, alignment, cohesion, and attraction-to-center rules. Even after the user scrolls to the later part of the timeline, the flock must still respond to the pointer’s viewport position.
