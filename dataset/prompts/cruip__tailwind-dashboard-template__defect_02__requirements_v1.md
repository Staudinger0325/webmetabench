Acceptance checklist:
## Public acceptance checklist

### R1 - Dashboard Layout and Main Content
When the user opens Dashboard and scrolls continuously from the initial viewport to the bottom of the page, they must see, in order, the Mosaic navigation on the left, the sticky top toolbar, the title and actions area, and a twelve-column responsive grid of cards covering sales summaries, channel breakdown, real-time value, country distribution, long-term trends, refunds, customers, activity, and income and expenses. At desktop, tablet, and mobile widths, the cards must wrap according to their defined column spans. On narrow screens, Top Channels and Customers must retain their own horizontal scrolling with the header and body columns aligned. When the user returns to Dashboard, the content container must be back at the top, and the top bar must not obscure the current card.

### R2 - Sidebar Expansion and Mobile Drawer
When the user clicks the Dashboard group on desktop, the sidebar must expand to show the full labels and the Main, Analytics, and Fintech items; collapsing it must restore the narrow sidebar. When the user taps the hamburger button at mobile width, the sidebar must slide in from the left with a backdrop, and the sidebar and backdrop must leave together after the user taps the close button, taps outside the sidebar, or presses Esc. After repeated rapid opening and closing, the hamburger button's expanded state, the drawer's visibility, and the backdrop's pointer interception must remain consistent. An invisible backdrop must never block the main content. The desktop expansion preference must be saved locally and restored after a refresh.

### R3 - Top Search and Menus
When the user clicks Search, Notifications, Need help?, and Acme Inc. in turn, the corresponding dialog or menu must open from the top area. The search panel must include a backdrop and automatically focus Search Anything…; Notifications must show its message list; Need help? must show Documentation, Support Site, and Contact us; and Acme Inc. must show Administrator, Settings, and Sign Out. After the user clicks outside the panel, presses Esc, or selects an item, the current overlay must close, its trigger must no longer appear open, and any backdrop must stop intercepting pointer input. The main content's scroll position, date range, theme, and card data must remain unchanged.

### R4 - Filter Popover State
After the user clicks Filter, the Filters popover must list Direct VS Indirect, Real Time Value, Top Channels, Sales VS Refunds, Last Order, and Total Spent, and it must allow multiple items to be selected in succession. Clicking Clear must clear every selection while keeping the popover visible; clicking Apply must retain the current result and close the popover. As the user repeatedly opens the popover, selects items, clears them, applies the result, or closes it by clicking outside or pressing Esc, the checkboxes must reflect the result of the most recent operation. Other menus, the card layout, chart data, and the real-time refresh sequence must not be reinitialized.

### R5 - Date Range and Popover Anchoring
After the user clicks the date-range button, the range calendar must open near the button and display the current start and end dates. When the user selects a new start date and end date, the button text, default month, and selected calendar interval must all use the same range, and closing and reopening the calendar must preserve that selection. While the calendar is open, the user may scroll the content area slightly upward and downward. The popover must move with the button's current on-screen position, keeping a fixed gap between their edges. Repeated scrolling in opposite directions must not accumulate extra displacement, and the popover must remain anchored to the button after scrolling stops. After the popover is closed and reopened, it must establish the same spatial relationship from the button's new position.

### R6 - Synchronized Real-Time Value Updates
When the user remains on Real Time Value through multiple refresh cycles, or opens Filter, the date calendar, or a top menu and switches themes while waiting, the data window must remove its oldest point and append its newest point. The large amount must use the current final point, the percentage must be calculated from the final two points, and the badge color must reflect the positive or negative direction. After every update, the amount, percentage, right end of the line, time axis, and hover tooltip must all belong to the same data batch. The text must not continue changing while the line remains still, and the line must not advance before the text catches up. Timed refreshes must stop when the user leaves the page, and only one update cadence may remain when the user returns.

### R7 - Theme Switching and State Preservation
When the user clicks the theme button, the page must switch between light and dark. The root page color scheme, sidebar, top bar, cards, text, borders, table dividers, chart coordinate grids, and tooltip must all adopt the corresponding colors, and the choice must be saved locally and restored after a refresh. During the color change, the current filter selections, date range, sidebar state, legend visibility, and real-time data window must not be cleared. Normal motion must resume after global transitions are briefly suppressed. When the user hovers over a chart again, the tooltip must use the new theme and still correspond to the current data point.

### R8 - Chart Legends and Hover Details
When the user moves the pointer over the Acme trend charts, Direct VS Indirect, Top Countries, Sales Over Time (all stores), Sales VS Refunds, and Reason for Refunds, the tooltip must appear near the current data element and show a value in the same unit as the card. Clicking an interactive legend must hide the corresponding bar group, sector, or line, and clicking it again must restore that data. Legend swatches, text opacity, summary meaning, and the series visible on the chart canvas must remain consistent at all times. After the viewport size or theme changes, each chart must readapt to its container and colors while preserving the user's current dataset visibility, and any replaced chart canvas must be removed.

### R9 - Channel and Customer Tables
When the user scrolls to Top Channels and Customers, the channel table must show sources such as Github.com, Facebook, Google (organic), Vimeo.com, and Indiehackers.com with their brand icons under Source, Visitors, Revenues, Sales, and Conversion. The customer table must show avatars, profiles, amounts, and flags under Name, Email, Spent, and Country. When the user narrows the viewport and scrolls either table horizontally, the headers must remain aligned with every row's cells. Channel icons, customer identities, highlighted amounts, and country information must correspond row by row. After switching to the dark theme, the backgrounds and dividers must still preserve a clear data hierarchy.

### R10 - Activity and Transaction Semantics
In Recent Activity, events must be grouped under Today and Yesterday and form a timeline with colored circular icons, descriptions of people or content, and a View entry. In Income/Expenses, transactions such as Qonto billing, Cruip.com Market Ltd 70 Wilson St London, Notion Labs Inc, Market Cap Ltd, and App.com Market Ltd 70 Wilson St London must be grouped under Today. Income, expenses, and canceled transactions must be expressed by their respective direction icons, colors, and struck-through amounts. Clicking an event or transaction link must perform only that link's corresponding interaction and must not change the chart window, filters, date, or theme on the same page.

### R11 - Promotional Banner and Page Lifecycle
After the user enters the page, the promotional banner containing Download on GitHub, Check Premium Version, and Close must appear in the visible bottom area. At desktop width it must be fixed in the bottom-right corner with its own shadow, while at mobile width it must extend horizontally along the bottom. Clicking Close must immediately remove the banner for the current session. Closing the banner must not reset the scroll position, sidebar, top overlays, date, theme, or chart data. Returning through the route must place the content back at the top. After the page is unloaded and recreated, keyboard, click, and scroll interactions, timed updates, and chart behavior must each run only once.
