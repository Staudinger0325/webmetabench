Acceptance checklist:
## Public acceptance checklist

### R1 - Document Entry and Two Editor Modes
After the user opens BlockSuite Playground and waits for the current document to be ready, clicking the top Switch Editor to switch back and forth between Page and Edgeless must make the main area show the block editor view and infinite canvas, respectively, while the same title, body text, and committed objects remain associated with the current document. Repeated switching must not create duplicate sample content. The canvas-specific zoom bar and creation tools must appear only in Edgeless; when the user returns to Page, those temporary menus must close, and the document text must retain its pre-switch committed state.

### R2 - Note Selection and Text Editing
When the user enters Edgeless, clicks a note, and starts typing in its body, the selection outline must fit the card's current bounds, the floating toolbar must show the actions applicable to the note, and the entered content must update only that note. After leaving text-editing mode, the user must still be able to select the same object. If the user then clicks a blank area of the canvas, switches to a creation tool, or changes the note's Show in scope, the selection, text caret, and related menus must close as required by that action. The next selection must not reuse the previous note's temporary height, stale bounds, or menu state; when editing resumes, both the caret and the content must belong to the current note.

### R3 - Exclusive Creation Tools and Independent Objects
As the user selects Select, Note, Pen, Highlighter, and Eraser in sequence and completes clicks or drags on the canvas, the bottom toolbar must highlight only the current tool at all times. Switching tools must close any menu that no longer applies to the previous tool and end that tool's temporary input. When the user repeatedly creates notes and strokes, each pointer-down-to-release gesture must form an independent object and an independent session-history entry. After switching back to Select, each object must be targetable separately, with its bounds, style, and selection state updating independently; a later gesture must not continue, append to, or replace an earlier object.

### R4 - Note Properties and Display Scope
When the user selects a note in Edgeless and uses the floating toolbar to adjust its Show in setting, Note Style, height mode, and Scale, the note content, outer card bounds, internal content scale, and where it appears in Page and Edgeless must update together from the current properties. After a property changes, the selection outline and floating toolbar must reposition from the new bounds. If the note leaves the current canvas display scope, the related selection must clear immediately; when the note is shown again and selected again, it must not reuse a closed panel, a stale size anchor, or the previous editing caret.

### R5 - Viewport Transform and Dot-Grid Synchronization
When the user clicks the lower-left zoom controls and scrolls over a blank area of the canvas in different directions, the percentage readout, notes, strokes, spacing between objects, selection outlines, hit areas, and dot-grid background must update continuously under the same viewport transform, while fixed interface tools remain at the browser edges. During zooming, the dot-grid spacing must follow the current scale; during panning, the dot-grid phase must move in sync with the world content. Zooming and panning back in the opposite direction must continue to preserve the spatial relationships between objects and must not separate visible positions, selection outlines, and actual click positions. After continuous operations, the percentage label must still represent the current viewport, and the zoom controls must remain usable.

### R6 - Live Anchoring of the Selection Toolbar
After the user selects a note in Edgeless and keeps it selected while continuously zooming, zooming back in the opposite direction, and scrolling the canvas, the floating toolbar must reposition each time from the note's current on-screen bounds. It must remain clearly associated with the note and its selection outline rather than staying at the coordinates from the moment of selection. When the note approaches any viewport edge, the toolbar must move to a side with enough space and remain within the visible area. When the object moves completely out of view, the toolbar must hide; if the object re-enters while the selection is still valid, the toolbar must reappear near that object, and its contents and menu state must continue to reflect the current note properties.

### R7 - Undo, Redo, and Session History
After the user creates a note, draws a stroke, uses Eraser, or changes an object property in the current document and then clicks Undo followed by Redo, the most recent committed operation must be reverted precisely in the document state and restored while the corresponding history remains available. Page and Edgeless must show consistent results for the same content. If the user starts a new creation or property change after undoing, subsequent history must follow the current branch. Switching modes must change only the presentation and must not split the same object's content and properties into separate, independent history states.

### R8 - Continuous Stroke Growth and Commit
When the user activates Pen or Highlighter and holds the pointer down on a blank area of the canvas to draw short lines, long curves, and paths across a large area, the currently visible path must grow continuously from its starting point through the positions already traversed. Previously drawn portions must remain visible throughout the gesture, and new portions must appear in sync with pointer movement. Regardless of the gesture duration or how many sample points are added, the path must not retract to its starting point or stop extending while the pointer remains down. On release, it must be saved as one selectable object whose final path matches the complete preview immediately before release; its path bounds must include every received movement, and the next pointer press must create an independent stroke from a new starting point.

### R9 - Shift Constraint, Pressure, and Stroke Style
While freely drawing with Pen or Highlighter, if the user holds and then releases Shift during the same pointer press, the path must remain constrained horizontally or vertically according to the initial direction of movement while Shift is held. After Shift is released, subsequent path points must immediately resume following the pointer, allowing one continuous stroke to contain both a constrained segment and a freehand segment. Pressure-capable input must change local stroke width only when the actual pressure changes. If the user adjusts the color or line width after completing the stroke, the entire path, selection bounds, and hit area must update together. After the pointer is released or the tool is switched, the next stroke must read the current input state again.

### R10 - Highlighter Transparency Compositing
When the user selects Highlighter from the Pen menu and holds the pointer down to draw self-intersecting curves, complete closed loops, and retraced paths, the single stroke formed during that pointer press must maintain one uniform semi-transparent color layer. Its self-crossings, closed joins, and repeatedly traversed regions must have the same opacity as the rest of that stroke. After the user releases the pointer and starts another Highlighter stroke across an existing stroke, the two independent objects must composite their respective color layers in the actual overlap region and display a darker color there, while their non-overlapping regions retain their respective colors, line widths, and opacity.

### R11 - Responsive Layout, Themes, and Remount State
When the user narrows and restores the window, switches between light and dark themes, and moves back and forth between Page and Edgeless, the Canvas dimensions, dot grid, object colors, selection bounds, and pointer hit detection must update in sync with the current viewport and theme, while committed document objects remain available. On a narrow screen, overflowing tools must move into More Tools or the advanced-tool navigation, the full-size zoom group must switch to a compact control, and the floating toolbar must preserve safe space from the screen edges. When the width is restored or the canvas is remounted, the controls must lay themselves out again; the temporary Pen submenu must remain closed and be available for the user to reopen.

### R12 - Releasing Direction Constraint During Freehand Drawing
During one continuous Pen gesture on the Edgeless canvas, after the user holds Shift to create a horizontal or vertical constrained segment and then releases Shift without releasing the pointer, the visible stroke tail must immediately resume following the true pointer path from the release point and allow drawing directly in any direction. The release point must not continue along the constrained direction, curl backward into a hook, create an extra loop, remain on the old tangent, or catch up later during subsequent input. The stroke must remain one continuous path throughout the gesture. After pointer release, the final stroke, endpoint, pressure appearance, and single history entry must match the user's actual input.
