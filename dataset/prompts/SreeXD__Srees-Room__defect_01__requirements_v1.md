Acceptance checklist:
## Public acceptance checklist

### R1 - Entry and Resource Preparation
When the user opens the page and waits for resources to be prepared, the page must first direct attention with a loading layer and resource progress, while pointer movement drives the visual response in the entry mask. After the user clicks to enter, the mask exits to reveal the complete 3D room, spatial text, and edge controls. Before the entry action is complete, the page must not expose an incomplete room or project hotspots that could be triggered accidentally. Once entry is complete, the scene, cursor prompts, music controls, and information panel enter the same explorable state, and repeated pointer movement does not restart the entry flow. Continued resource buffering must not clear the entry view once it has been established.

### R2 - 3D Camera Exploration
On desktop, when the user presses and drags in the scene, the camera must rotate continuously with the pointer displacement to view the room, and releasing must immediately stop applying further camera movement. Scrolling must update the camera distance smoothly and keep it within usable viewing bounds. On a touch device, one-finger dragging and changing the distance between two fingers must produce rotation and zoom, respectively, with the same semantics. After the fingers leave the screen, stale input state is cleared, while hotspot hit detection, spatial text, and fixed controls remain synchronized with the current viewport. Clicks on edge controls must not be misinterpreted by scene gestures as camera movement.

### R3 - Room Objects and Project Media
After entering the room, the user must be able to see the portrait, pet, plant, clock, robot, speaker, and three project screens within one continuous scene, with the spatial text LibXD, Xwing webpage, and Aeons beside the screens remaining associated with their respective objects. As the user moves the camera or waits while the scene runs, the project screens continuously loop muted videos, while the clock and robot head continue their time- and camera-related motion. Switching between day and night must neither interrupt the video surfaces nor cause the spatial text to detach from its original objects.

### R4 - Hotspot Prompts and Object Details
When the user hovers the pointer near the portrait, project screens, social icons, or Resume object, the custom cursor must display a prompt that matches the current target. After the pointer leaves the hit area, the prompt returns to a blank exploration state. When the user clicks the portrait or a project screen, the top-left information panel updates to show that object's title and description; clicking empty space in the scene afterward must clear the focus and old details. Repeatedly switching among different objects must leave no text, links, or highlight state from the previous object. Passing over a hotspot while dragging the camera must not turn a transient hover directly into the details focus.

### R5 - External Profile Destinations
When the user clicks the spatial icon corresponding to Github, Twitter, Youtube, Linkedin, or Resume, the page must open the external destination associated with that icon while preserving the existing state of the room, camera, and controls. This action is handled separately from focusing the portrait and project details: after an external destination is clicked, the top-left information panel must not be populated with unrelated project content. When the user returns to the original page and continues hovering, dragging, or clicking, hotspot prompts and focus-clearing rules continue to update normally for the current target.

### R6 - Day/Night Appearance Switching
When the user clicks the day/night control in the top right, the room background, baked environment texture, plant brightness, and foreground of the controls overlay must transition continuously as a single theme state, and the icon must update to indicate the opposite switch available next. The room material and plant material must share the same transition progress, advancing their brightness changes in sync during the transition instead of making the plant wait until the room transition finishes and then switch instantly. When the user clicks again to return to the other appearance, the current camera, object focus, project videos, and music controls remain active, while the clock and robot head continue moving. The initial appearance may be determined by local time, but after the user has switched it, the view must use only the latest theme state.

### R7 - Music and Speaker Rhythm Synchronization
When the user plays the background music after completing entry and enabling sound, the music control at the bottom left must show playback progress, and the speaker in the upper-right part of the room must continue scaling rhythmically in step with the same music state. When the user pauses the music with the bottom-left control, audio progress stops and the speaker immediately stops its rhythmic scaling and holds at a static scale. After playback resumes, both resume together. Repeated pausing, playback, or theme switching must never separate the visible rhythm from the actual music state. While the music is paused, independent dynamics including the clock, project videos, and plant continue to update under their own rules.

### R8 - Sound Permission and Control Feedback
When the user clicks the sound control in the top right to enable or disable sound, the control icon and hover prompt must reflect the current sound permission, and both interface click sounds and background music must obey that permission state. Operating the bottom-left music control while sound is disabled must not produce audible output without permission. Once sound permission is restored and music is played, the controls, progress state, and rhythm in the room reestablish a consistent relationship. Repeated clicks must not layer multiple background tracks or leave conflicting playback icons. At all times, the control icon must express only the sound action currently available.

### R9 - Exploration Progress Boundaries
When the user clicks an explorable portrait, project screen, social icon, or Resume object for the first time, the bottom-right Explored display must update to reflect the number of objects discovered. Clicking the same object again must not count the same discovery more than once. Clicking empty space in the scene, dragging the camera, or switching the theme does not create a new exploration record, and the discovered state remains readable throughout the same experience. After the user re-enters the page, the progress display must start from the new page session and must not mix with remnants of the old session. Returning to the original room after opening an external profile destination must not add the discovered object again.

### R10 - Full-Viewport Layout and Lifecycle Adaptation
When the user resizes the browser viewport or opens the page on a mobile device, the 3D room continues to fill the visible area. The top-left details, top-right theme and sound controls, bottom-left music control, and bottom-right exploration display remain near their respective edges and operable. When the user waits for resources, switches to another page and returns, or re-enters the experience, the loading state, animation playback, video surfaces, and input handling must each resume in a single effective state. Old dragging, zooming, or audio-control state must not continue to affect the layout or motion in the newly displayed view.

### R11 - Synchronized Day and Night Material Transition
When the user switches the 3D room between day and night, the walls, desk, room structure, and plant leaves must use the same current transition progress and blend continuously in the same direction toward the selected appearance. No surface may reverse, pass beyond either endpoint and return, or briefly move toward the opposite theme from the rest of the room. If the user switches again before the transition finishes, every material must turn from its currently visible state toward the latest selection, while the theme icon, guidance text, and final room appearance continue to indicate that same target.
