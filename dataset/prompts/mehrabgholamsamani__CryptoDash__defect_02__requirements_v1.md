Acceptance checklist:
## Public acceptance checklist

### R1 - Local Sign-Up and Profile Entry
When the user first opens the app and the browser has no local profile, the page displays the data-reliability notice and a form with Name, Email, and Password. The submit button is enabled only when the trimmed name has at least 2 characters, the email format is valid, and the password has at least 6 characters; any profile that satisfies these rules can enter Market. After submission, the welcome title and Account use the submitted name and lowercase email, while the password does not appear in any later display. Once the notice is dismissed, it remains dismissed after a refresh; clicking Sign out clears the current user and returns to a blank Sign up form.

### R2 - Navigation, Range, and Persistent State
When the user clicks Market Overview, Watchlist, Compare, or Settings in the desktop Sidebar, expands or collapses Coin Details, or selects a coin within Coin Details, the right-hand content, header title, subtitle, active item, and current coin update in sync within the same app shell. The header always retains the four time ranges and the theme control. As the user moves between pages or refreshes the browser, the profile, range, favorites, and appearance preferences are restored locally, while a refresh returns to Market. Corrupted local content falls back to safe defaults and does not populate a new form with data from the previous profile.

### R3 - Market Overview and Coin-Card Strip Interaction
When the user enters Market, presses and drags horizontally on the desktop coin-card strip, releases the pointer or moves it out of the strip, and then clicks a card or a Top Coins row, the strip's drag state ends when the pointer is released or leaves the strip, and the selected coin opens in Coin Details. The cards, 24h Volume, trend chart, Breadth, Volatility & Risk section, and table all use the currently available market data. The trend chart always uses the 7d sparkline and displays a Some data is limited notice for other ranges; Breadth counts only valid values in the field for the selected range, and every risk name, value, bar, and rating uses the same available series. The card strip and corresponding charts show skeletons while loading, and narrow screens switch to a touch-friendly grid with expandable Market Breadth and Volatility & Risk panels.

### R4 - Coin Price Chart and Controls
When the user opens a new coin from navigation, Market, or Watchlist, the coin profile and history enter separate loading states, and the price chart and Market Metrics show their respective skeletons. When only the range changes, only the historical chart enters a loading state, while the existing title and summary remain until the current response arrives. Once the new responses arrive, the icon, price, 24h change, Range High, Range Low, time labels, and price chart update for the current coin and time window. Clicking MA20/50 toggles both moving averages as a group, and Log scale maps only valid positive values. If history loading fails, the existing successful chart is restored with a Some data is limited notice; Chart unavailable appears only when there is no series to retain, and an earlier request cannot overwrite the current view.

### R5 - Supply View and Technical Indicators
When the user scrolls to Tokenomics and Indicators, the supply doughnut chart, Circulating, Remaining, estimated values, and scarcity label stay synchronized with the current supply fields. When no valid supply cap is available, the view expresses Uncapped / Unknown, the values for Remaining and Est. FDV display an em dash, and the Remaining description reads No max supply; if circulating supply is also unavailable, the view enters the Not enough supply data state. With sufficient history, RSI (14) and the fixed 70 (Overbought) and 30 (Oversold) horizontal lines use a y-axis from 0 to 100, while MACD 12/26, Signal 9, and Histogram share the same labels. Clicking the Histogram legend makes the bars transition continuously out of view or back into view while the lines remain; the legend strikethrough state, the set of bars available to the tooltip, and the final bar visibility all stay consistent.

### R6 - Favorites and Watchlist
When the user clicks the star in Coin Details, its outlined or filled state, the locally saved deduplicated favorites, and the Watchlist candidate set toggle in sync. In Watchlist, the user can filter by entering a name or symbol, choose Market Cap, Price, 24h %, or Volume as the sort key, switch between ascending and descending order, use Open to navigate to a coin, and use Remove or Clear to update the favorites collection. During a refresh, the button enters a loading state and existing rows remain. After a successful refresh, rows from that refresh replace the table and the update time changes; after a failure, the previous successful rows and an explanatory notice remain. Clear displays the empty-Watchlist guidance, while No data loaded yet appears when favorites exist but a completed refresh still has no successful market data.

### R7 - Multi-Coin Comparison
When the user enters Compare from Watchlist, clicks candidate coins to select or deselect them while keeping no more than 4 selected, and switches between % Performance and Price, the line series, legend, and tooltip use the current historical range. In Comparison Summary, Current and 24h come from the market data saved alongside the currently displayed history, while Start, End, Return, Volatility, and Max DD are derived from that history. Log scale is cleared automatically when the user leaves Price. While at least one coin remains selected, changing the selection or range aborts or invalidates the previous request. If only some history is available, the available series remain displayed and the missing selections are listed. If the entire batch fails, an existing successful chart and summary are retained only when they match the current selection; No chart data yet and No history returned appear only when there is no matching history to retain.

### R8 - Appearance Preferences and Theme Transition
When the user selects Light, Dark, an accent color, Compact, Reduce motion, or a currency in Settings, or clicks the header theme button, the selected control states, affected page colors, and local preferences synchronize immediately. With Reduce motion off, both Light/Dark entry points start a radial color expansion from the top-right corner that covers the viewport; page backgrounds, cards, text, borders, and shadows change color continuously during the process before settling into the target theme. Rapidly clicking the opposite theme clears the previous process and restarts it for the last selection, and a refresh restores the final theme. With Reduce motion on, the theme still genuinely changes and is saved, but the radial expansion does not play, and the final button states and page colors remain consistent.

### R9 - Preference Maintenance, Market Data, and Session
When the user clicks Reset preferences, Clear API cache, or Sign out in Settings, the three actions retain clear boundaries: Reset preferences restores the default appearance, currency, and range; Clear API cache clears locally stored market data and briefly confirms completion; only Sign out removes the current user and returns to Sign up. After Reset preferences or Clear API cache, the current name, email, and Watchlist remain. After Sign out, favorites and preferences remain stored locally. During the session, Account always displays the currently submitted name and lowercase email and never displays a password or fixed example profile.

### R10 - Responsive Layout and Data Lifecycle
As the user narrows the viewport, the desktop Sidebar is hidden and replaced by a fixed top navigation containing Market, Coins, Watch, Compare, and Settings. The header stacks vertically, the market coin area contracts from two columns to one on an extra-narrow screen, the main chart, Tokenomics, and Indicators switch to single-column layouts, and the Watchlist and Compare tables allow horizontal scrolling while retaining fixed minimum column widths. When the user scrolls beyond the first screen, changes the viewport, rapidly switches pages, or waits for data to recover, charts adapt to their current containers, and requests or timed processes from views the user has left do not overwrite the new state. The card strip, charts, or indicator areas that have dedicated loading placeholders show skeletons, while existing content, limited-data notices, and empty states appear according to each page's fallback rules.
