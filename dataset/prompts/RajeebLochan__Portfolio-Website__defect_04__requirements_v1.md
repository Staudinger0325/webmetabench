Acceptance checklist:
## Public acceptance checklist

### R1 - Fixed Navigation and Narrow-Screen Menu
When the user opens the page on a wide screen and scrolls down, the top of the page must continue to display the Rajeeb brand and the Home, About, Project, and Contact links in a horizontal row. Clicking a link must smoothly scroll to the corresponding section, and the Hero canvas, project previews, and project details overlay must not cover the navigation text. When the user clicks the menu icon on a narrow screen, the four links must appear in a vertical list below the fixed bar and the icon must switch to its close state. Clicking it again must collapse the list and restore the menu icon. The scroll position, page width, and currently rotating capability keyword must each retain their current state before and after the menu opens or closes.

### R2 - Hero 3D Scene and Scroll Parallax
When the user enters the Hero, waits for the 3D assets, moves the pointer, and scrolls down, the canvas must first show a real-time loading percentage and then replace it with a continuously floating astronaut once loading completes. The camera must make small, damped movements around the default view in the pointer's direction, while the identity text remains readable at all times. As the user continues scrolling down or reverses direction toward the top, the sky, near and far mountain layers, and planets must move continuously according to their respective directions and amplitudes and move back in step with the scroll progress. Their front-to-back layer order must not change, and after the user returns to the top, the scene must once again correspond to the top scroll position.

### R3 - Capability Keyword Rotation
While the user remains in the Hero and waits through capability keyword changes, the current word must exit toward the upper right as a complete unit while its opacity decreases and its blur increases. The incoming word's characters must move in sequence from offset, blurred, transparent states into the clear primary position. During the transition window, only the incoming and outgoing word layers needed for that cycle may remain. After each animation finishes, all characters of the outgoing word must disappear together, leaving no detached suffixes, duplicate letters, or ghost images around the new word. After multiple consecutive cycles, returning after switching browser tabs, or changing the viewport, the rotation must still represent only its current state.

### R4 - About Cards and Draggable Globe
When the user scrolls to About Me and successively hovers over the > whoami identity card, My Reads card, Time Zone card, Services Offered card, and Tech Stacks card, each card must rise slightly and return to its original grid position when the pointer leaves. Images, descriptive text, service entries, and orbiting content must remain inside their respective cards at all times. When the user presses and holds the globe and drags it horizontally, the cursor must change from grab to grabbing and the globe must continuously change its angle in the drag direction. On release or pointer exit, the cursor must return to grab and the globe must resume automatic rotation. Repeated drags must continue from the current angle without resetting any state in the other cards, projects, or form.

### R5 - Technology Icon Orbits and Hover Feedback
While the user watches the two rings of icons in the Tech Stacks card, the icons corresponding to the current technology data must orbit continuously at different radii and in opposite directions. The icons must remain upright and recognizable, and the low-contrast orbit lines must not obscure the title or capability description. When the user moves the pointer over any icon, that icon must enlarge slightly while continuing to orbit along its original path. When the pointer leaves, the icon must return to its regular size without interrupting its orbital phase. As the user moves continuously across multiple icons, the scaling feedback must apply only to the icon currently under the pointer; the movement of the inner and outer rings and the sizes of all other icons must remain independent.

### R6 - Project List and Pointer-Following Preview
In My Selected Projects, when the user moves the pointer into any project row and then within that row, the current project's preview media must appear near the pointer and follow its coordinates with continuous, damped motion, while the title, technology tags, and Read More action remain readable and clickable. When the user quickly switches between hovered rows, the preview must switch in sync to the new row's media. Once the pointer leaves the project area, the preview must be removed completely. The project title, tags, preview image, and details must all come from the same current project entry. The project count must update with the current project data rather than remain fixed at the count from any particular visit.

### R7 - Project Details Overlay Lifecycle
When the user clicks Read More for any project, the page must open a centered project details overlay with background blur over the current page position. It must display the selected project's image, title, summary, extended description, technology information, and View Project external link. The underlying pointer-following preview must not appear in front of the backdrop. When the user clicks the close icon inside the details overlay, the backdrop and details content must both be removed, returning the user to the original list position. If the user then opens the same project again or selects another project, all text, media, tags, and the destination address must update to the most recently selected project.

### R8 - Work Experience Timeline Progress
As the user scrolls from the projects section to My Work Experience, the dates, role or project name, organization, and responsibility paragraphs for the current experience entries must be readable along the vertical timeline. The Data Analyst Intern content at Sure Trust and the IBM SkillsBuild – AI & Cloud Internship content must remain associated with their respective entries. As the user reads downward, the highlight on the thin line must progress from the top according to the actual content height. When the user scrolls in reverse, it must retract along the same path, without changing the node order or swapping dates and body text. After switching between wide and narrow layouts, the dates and organizations must reflow according to the corresponding layout, and the timeline must remain synchronized with the experience entries.

### R9 - Contact Form Submission States
When the user enters content separately in Full Name, Email, and Message and submits the form, the three fields must retain their values independently and enforce required-field and email-format constraints. The particle canvas must not block field focus, keyboard input, text selection, or button clicks. During a valid submission, the button must change from Send to Sending... and preserve the entered content. After a successful submission, all three fields must be cleared and You message has been sent! must appear. If the submission does not complete, the loading text must end, the editable content must be preserved, and Somthing went wrong! must appear. After the message dismisses automatically, the user must still be able to submit again.

### R10 - Canvas Responsiveness and Footer Links
When the user resizes the window, switches between wide and narrow layouts, and continues browsing, the globe and the contact-section particle canvas must redraw to the new container dimensions, with the particles remaining behind the form. The 3D astronaut, cards, project rows, project details, and long text must reflow within their containers without producing horizontal scrolling. When the user reaches the footer, Terms & Conditions, Privacy Policy, X, Linkedin, GitHub, and the copyright information must be visible. When the user clicks a project's View Project link or a social icon, the destination address must correspond to the current project or the respective platform, and the rest of the page must remain browsable.
