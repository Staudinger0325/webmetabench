Acceptance checklist:
## Public acceptance checklist

### R1 - Startup and Desktop Entry
When the user opens AqadilOS, the black terminal-style startup screen must advance the system preparation messages and entry prompt line by line, then exit completely so that the wallpaper, desktop icons, bottom taskbar, and system status area all become visible at the same time. If the user immediately double-clicks an icon or clicks a taskbar entry after startup finishes, the desktop must receive the input; the startup screen must no longer obscure windows, icons, or the taskbar or retain a transparent layer capable of intercepting clicks. The selection-box feedback created by pressing and dragging on an empty desktop area must disappear promptly upon release.

### R2 - Window and Taskbar Coordination
When the user double-clicks a desktop icon or clicks an app entry in the Start menu, the system must open the corresponding window with a title bar and content area and show that app's open state on the taskbar. Opening the same app again must focus the existing window, and restoring it from the taskbar after minimization must restore that same window. When the user clicks a different window or an open taskbar entry, the active window must move to the front and update its active appearance. Closing a window must remove its taskbar state in sync, window content must not be created more than once, and switching the active window must not reset the open content or position of any other window.

### R3 - Dragging, Resizing, and Maximization
While the user holds and drags a window's title bar, the window must continuously follow the pointer and remain within the available viewport boundaries above the taskbar. When the user resizes a non-maximized window from a corner, the outer frame and internal content area must update together. When the user clicks the maximize control or toggles the window state again, the window must first fill the space above the taskbar and then return to its most recent non-maximized position and size. Title-bar movement and corner resizing must not occur while the window is maximized, and scrollable content inside the window must remain within that app's content area.

### R4 - Start Menu and Game Entries
When the user clicks the Start button, the Start menu must appear from the bottom and display the search field, Pinned section, Recommended section, and user area. Clicking outside the menu must collapse it, while clicking a regular app entry must open the corresponding window and collapse the menu at the same time. When the user clicks Games, the Games panel must expand beside the menu and allow available games to be opened. Clicking inside the panel must not dismiss it inadvertently; after a click outside the panel, the menu's outer layer and the Games panel must leave their current expanded state together.

### R5 - Document Workspace and Tools
After the user edits the body text in Resume.txt and saves it, the window must change from an unsaved state to a saved state; closing and reopening it must restore the saved text and filename. Creating a new document, exporting, and restoring the built-in content must affect only the current document workspace. When the user expands folders in Project Files, switches dashboard content, enters a filter term, or enters File Explorer, the left-hand tree, current directory, filtered list, and content panel must update in sync with the current selection. Input results from Akadilium Browser, Terminal, and Calculator must likewise be displayed within their respective windows.

### R6 - Synchronized Music Playback State
When the user clicks play, pause, a track row, previous, next, or a position on the progress bar, the Music Player playback controls, time text, progress bar, current-track highlight, cover background, record rotation, and right-side waveform must synchronously reflect the same media state. If the interface still shows playback and the progress continues to update after the user minimizes the window during playback and restores it from the taskbar, the actual audio and waveform must continue advancing as well. After the user pauses playback or closes the window, progress, rotation, and the waveform must all stop and enter a clearly non-playing state.

### R7 - Calendar and Personalization Windows
When the user changes the Calendar month, clicks a date, or submits a new event, the month heading, date grid, selected date, clock, and event summary in the current window must update in sync. After the event-creation overlay closes, the corresponding date view must be restored. When the user selects a wallpaper in Settings & Personalization, clicks a card or drags to switch contacts in Contact Me, or switches bank cards and returns to the card view in Support / Donate, the desktop background, active contact details, and current-card indicator must update respectively, while the content and stacking order of other windows are preserved.

### R8 - Neon Drift Motion Reference and Collision Lanes
After entering Neon Drift, keyboard directional input or a horizontal swipe must continuously control the vehicle as it moves between lanes, while obstacles, the score, and the game-over state update in sync with the game loop. While the vehicle appears to travel forward and obstacles continuously approach, the ground grid must scroll toward the rear of the vehicle at a reference-frame speed matching the speed at which the obstacles approach. After consecutive lane-change commands have been accepted, collision eligibility must be determined by the current discrete target lane. While the vehicle model is visually interpolating over other lanes, it must not additionally collide with obstacles in the lanes being crossed. After a collision, the grid, obstacles, and score progression must all stop at the same time; restarting must begin a new running state.

### R9 - External Navigation Confirmation Overlay
When the user clicks GitHub, Telegram, AkadilEDU, or an external-site entry in the browser, a darkened backdrop and a Security Gateway card must appear together above the desktop. The card must show the target identity, full address, Cancel, Open Link, and a close control, and it must block input to the underlying interface while present. After the user clicks Cancel, the close control, or the backdrop, the confirmation card and backdrop must disappear as part of the same exit state. As soon as the card disappears, the desktop icons, Start button, taskbar, and existing windows must immediately regain their clicking, dragging, minimizing, and opening capabilities.

### R10 - Responsive Layout and Session Cleanup
When the user narrows the viewport, opens a window with long content at a mobile size, restores a window after minimizing it, or repeatedly enters the same app, the taskbar must retain operable entries, windows must not cover the bottom taskbar, and long content must scroll inside its window while the desktop remains fixed. After the user closes the music player, cancels external navigation, closes the menu, or ends a game, reopening the corresponding entry must not inherit a dismissed backdrop, invalid focus, stale media activity, or an ended game state. The new session must begin in the operable state prescribed for that app.

### R11 - Cyber Lock Alignment Evaluation and Input Gating
In Cyber Lock, each locking input must be evaluated only against the current alignment of the active ring and the target line on the right. After one ring is successfully locked, subsequent input must remain disabled until the next ring becomes active and begins its own independent evaluation. Rapidly pressing Space or clicking repeatedly must not reuse the previous ring's successful result, skip the next ring's alignment check, or lock two rings within the same snapping cycle. The ring count, lives, target-line feedback, and visible snapping animation must advance in sync.
