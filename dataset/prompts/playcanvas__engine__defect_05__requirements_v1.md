Acceptance checklist:
## Public acceptance checklist

### R1 - Workspace Entry and Scene Readiness
When a user navigates directly to Shaders / Integer Textures, Graphics / Shadow Cascades, or Physics / Vehicle, the central area first displays the LOADING overlay. The overlay is removed only after the current page's canvas, graphics device, Source content, instructions, and input data are ready, at which point Active Device and the interactions already provided on that page become available. If resources fail to become ready, the page retains Example failed to load and the corresponding message and does not mark an empty canvas as ready. Refreshing the currently selected example repeats the same loading process, and imagery and input state from the preceding instance must not show through the overlay into the new instance.

### R2 - Example Navigation and Content Switching
When a user enters free text, a category tag, or an example tag in the Filter, category:, example: field, the categories and thumbnails narrow to match the current input. After the user clicks a matching entry, the old page exits, the target entry enters its loading state, and the canvas, Source contents, Controls, Info, and attribution content are replaced in sync. Clearing the input restores the full navigation, and No results appears when nothing matches. Clicking the currently selected entry again refreshes that example, Large thumbnails changes only the browsing density, and if the user selects entries repeatedly while loading is in progress, only the final route is allowed to finish and respond to subsequent input.

### R3 - Brush Input on the Sand Canvas
When a user moves the pointer within the Integer Textures square wall surface, the white circular brush outline follows the wall-surface coordinates. Holding the left mouse button and dragging continuously writes the current material along the pointer path, while holding Shift and using the left mouse button or holding the right mouse button and dragging continuously erases the covered area. Releasing the button, moving the pointer out of the square wall surface, or canceling the pointer immediately stops the corresponding edit. After a viewport change, panel opening or closing, or a fullscreen transition, the ring center, brush radius, and actual deposition point remain aligned on the rearranged square wall surface. Right-clicking does not open the browser context menu, and repeated presses and rapid reverse drags affect only the areas the pointer actually traverses.

### R4 - Material Selection and Wall Behavior
When a user presses number key 1, 2, 3, or 4 and continues drawing on the Integer Textures wall surface, subsequent strokes use Sand (yellow sand), Orange Sand, Gray Sand, and Stone (the wall material), respectively. The warm-yellow, orange, and dark-gray particles and the medium-gray obstacles retain distinguishable colors and light-and-dark variation, and changing the selection does not rewrite previously placed material. Both user-drawn walls and the initial horizontal wall remain stationary and block particles; after a local part of a wall is erased, only the opening covered by the brush becomes empty. Rapid consecutive material selections use the last valid selection, while the surrounding unerased wall, existing sand piles, and page-shell state remain unchanged.

### R5 - Sand Accumulation and Obstacle Response
When a user continuously adds sand above the center of the initial horizontal wall and waits for it to fall, particles preferentially enter empty space directly below and, when blocked, split according to the actual open space on the left and right, so the sand pile grows continuously around the collision area. When the user then erases a small opening in the wall, unsupported particles above it fall through the opening and form a new pile below. Long-running evolution may retain random details and locally asymmetrical contours, but the entire pile must not drift continuously in one fixed horizontal direction or form parallel bands sustained over time by a one-direction bias. Intact walls and boundaries remain impassable at all times.

### R6 - Sand Reset and State Isolation
After drawing multiple materials, cutting an opening in the wall, and waiting for the particles to redistribute, when a user presses Space, the entire current simulation returns to a valid initial state containing a horizontal wall in the lower-middle area and scattered particles. The previous user strokes, wall openings, and sand-pile positions are cleared, and gravity-driven evolution continues from the new state. Across multiple consecutive resets, each corresponding reset occurs once, on key release; it does not reload the entire Examples browser or change the current route, Active Device, filter text, thumbnail density, fullscreen state, or mobile panel. After the user leaves the page, the old instance no longer responds to Space.

### R7 - Shadow Scene and Orbit Camera
When a user enters Graphics / Shadow Cascades and drags the mouse, scrolls the mouse wheel, or performs touch-rotate and pinch gestures within the 3D canvas, the camera continuously changes its orientation and distance around the tree focus. The low-poly terrain, sky, moving clouds, directional light, and shadow projections continue coherently within the same space as the viewpoint changes, and inertia gradually settles after release. Consecutive reverse drags, repeated zooming, and pointer cancellation do not accumulate residual displacement, and the cloud trajectories do not pause because of camera input. After panel rearrangement or a viewport change, the focus remains on the scene's main subject, and touch gestures do not trigger page selection or browser zoom.

### R8 - Shadow Parameters and Filtering Synchronization
When a user selects any listed PCF1_32F, PCF3_32F, PCF5_32F, PCF1_16F, PCF3_16F, PCF5_16F, VSM_16F, VSM_32F, or PCSS_32F filtering option in Shadow Cascade Settings and drags Count, Resolution, Distribution, Blend, VSM Blur, PCSS Penumbra, or PCSS Falloff, the selected option, slider position, displayed value, and directional-light state remain continuously synchronized. The terrain shadows change continuously in the corresponding dimensions of detail, distance allocation, overlap transition, blur, penumbra, and falloff. The final value is retained on release, and rapid back-and-forth input retains only the latest input. Switching to another filtering family and then returning preserves the values previously set for each family. Parameter interactions do not stop the clouds, replace the terrain, or reset Every Frame or the camera pose.

### R9 - Cloud and Cloud-Shadow Temporal Continuity
When a user keeps the Shadow Cascades camera stationary while watching the moving clouds and their projections on the terrain, turns off Every Frame and continues waiting, and then slowly rotates the camera to view cloud shadows in different locations, the reduced-shadow-update-overhead state still keeps all visible cloud shadows across the terrain following the cloud positions promptly and continuously, preserving the same temporal relationship. When the user repeatedly turns the switch off and back on, the cloud trajectory, camera pose, filtering mode, and all other control values retain their current states. While the switch is off, the shadow layer must not broadly pause and then jump; when it is turned back on, per-frame correspondence resumes immediately without reloading the scene.

### R10 - Vehicle Physics Scene and Shadow Continuity
When a user enters Physics / Vehicle and drives the vehicle within the 3D canvas using the keyboard or mobile buttons, the vehicle falls under gravity to the ground, the front wheels steer, the rear wheels drive, and the vehicle gradually stops because of friction after the controls are released. When the user drives the vehicle into the wall of blocks, the blocks scatter under the collision force, and the motion of the vehicle and blocks follows rigid-body dynamics. The camera tracks the vehicle's position at a fixed offset and follows it smoothly as it moves. The directional light casts shadows for all dynamic objects in the scene. As the vehicle or blocks move within the camera view, whenever an object itself is visible, its shadow remains visually synchronized with its position and neither disappears suddenly nor undergoes a discontinuous visibility transition as the distance between the object and camera changes. The visible shadow range remains consistent with the scene's visual presentation. After the user presses R to reset, the vehicle and blocks return to their initial positions with zero velocity, and shadow casting continues from the new state.

### R11 - Graphics Device Selection and Fallback
When a user selects WebGPU, WebGL 2, or Null from Active Device, the current Integer Textures, Shadow Cascades, or Vehicle example enters a clear reload process and, when it finishes, is rendered by the device that was ultimately activated. The selector prefix remains synchronized with the actual active device name, while the route and navigation selection continue to point to the original entry. If the current browser does not support the selected backend, the corresponding option displays not supported and an available fallback device is used. The Null state does not retain the enabled appearance for MiniStats. After the user returns to a rendering-capable device, the canvas is recreated and the current page's applicable capabilities return: brush input for Integer Textures, camera and parameter controls for Shadow Cascades, or keyboard input and physics simulation for Vehicle.

### R12 - Sharing and Presentation Tools
When a user clicks the MiniStats, attribution, or fullscreen entry, the page respectively toggles the performance overlay, the current example's asset attribution, or an expanded canvas, and the selected appearance of each button remains synchronized with the visible content. In fullscreen, moving the pointer temporarily reveals the menu; pressing Escape returns to the preceding workspace and recalculates the canvas size. After opening Share this page, the user can view a read-only link and social sharing entries. Clicking Copy displays Copied, and pressing Escape, clicking the close button, or clicking the backdrop closes the dialog. A recipient who opens the link returns to the same example in the full Examples browser with valid state restored; an invalid payload uses the page's default state.
