You are testing a deployed frontend implementation against the acceptance checklist below.

Use the browser like a black-box QA tester. Explore the relevant pages, interact with the UI, and use screenshots or video recordings when a requirement involves motion, timing, visual effects, input response, or multi-step state changes.

Check the checklist items one by one and determine how well the implementation satisfies them. Report your findings, including any unmet checklist items, the observed behavior, and concise evidence from your browser interactions.

Acceptance checklist:
## Public acceptance checklist

### R1 - Initial View and Customization Transition
When the user opens the page in a desktop or mobile viewport, the same full-screen 3D canvas must initially show a warm-yellow T-shirt, a triangular wireframe Logo, front text, the brand heading, descriptive copy, and the "Customize It" button. After the user clicks "Customize It," the introduction content exits while the editing controls on the left, layer controls at the bottom, and "Go Back" control at the top right enter from their respective directions, with the model remaining visually continuous from the frame before the transition. If the user quickly returns to the introduction and then reenters customization, the page must still contain only one canvas, and the selected shirt color, assets, text, visibility combination, and camera angle must persist. Switching interface states must not duplicate the model, replay the initial values, or alter any data in the current session.

### R2 - Model Orbit and Zoom
When the user presses and holds on the canvas in customization mode and drags horizontally or diagonally, the camera must orbit continuously around the same T-shirt so that the front, side, and back enter view in sequence. The Logos, text, full-shirt texture, fold shading, and mesh must always move together as one spatial object. Using the mouse wheel must change only the viewing distance, while the document position remains fixed. After the user releases the pointer or stops using the wheel, the camera must remain at its current angle and distance, and subsequently clicking an editing button must not also rotate the model. A new drag must continue from the existing view; when the camera returns to the front or back, the content, orientation, and occlusion relationships for that side must match the previously configured state.

### R3 - Linked Shirt Color Styling
When the user opens the color control on the left and selects a new color in the visible color field, the T-shirt's base material must transition frame by frame from the current color to the selected value while the model remains visible throughout the transition. Filled action buttons and enabled layer controls at the bottom must adopt the same color, using black or white text according to the color's brightness, without overriding the colors of the front or back text itself. If the user selects several colors in succession, switches to another panel and returns, or temporarily returns to the introduction, the last selection must continue to drive the shirt and related control states. A color change must not reset any Logo, texture, text layout, layer visibility, or camera angle.

### R4 - Side-Specific Built-In Asset Selection
When the user opens the asset control, three groups of circular thumbnails labeled "Textures," "Front Logos," and "Back Logos" must appear in separate internally scrolling areas. Selecting a texture must replace only the current full-shirt texture asset, while selecting a front or back Logo must update only the targeted side and display it on the next redraw; the Logo on the other side, the text on both sides, the shirt color, the visibility combination, and the camera angle must retain their existing values. If the user selects a back Logo while the camera faces the front and then drags around to the back, the newly selected back asset must be visible. When the user selects different thumbnails from the same group in succession, the last selection must take effect; after switching to another editing control and returning, the group contents and the current model state must still correspond.

### R5 - Image Selection and Full-Shirt Coverage
When the user opens the image control, the panel must initially display "No file selected." After the user selects a supported local image, the panel must display that image's filename. When the user clicks "Full," the application must wait for reading to complete, close the panel, make the new image the full-shirt texture, and place the full-shirt texture control at the bottom into a semi-transparent enabled state colored with the current shirt color. The coverage must be viewable on both the front and back as the camera orbits the model. If the user selects another image and applies "Full" again, the most recently applied image must replace the previous one without rewriting the front or back local Logos, text content, or their respective visibility values. When no image has been selected, the panel must remain in its empty state and empty content must not overwrite the current model.

### R6 - Front and Back Logo Geometry Controls
When the user opens the Logo controls and repeatedly clicks the minus or plus actions for the front X, Y, Z, or size values, each click must move or scale the front Logo graphic from its current parameters, and the canvas must redraw immediately without changing the view. After dragging the model around to the back, using the corresponding back actions must change only the back Logo graphic; it must not write those values to the front or move the text or full-shirt texture. The accumulated position and size must persist after rapid repeated clicks, switching to the color or text control and returning, or hiding and restoring the Logo on either side. When restored, the graphic must return with the geometry it had before being hidden, and while the model rotates, the decal must remain attached to the shirt's curved surface without drifting across the screen.

### R7 - Front and Back Text Layout
When the user enters front content at the top of the text panel and adjusts its three-axis position, three-axis rotation, three-axis scale, font, or color, the front text decal must update with every input and action. After the user scrolls internally to the bottom of the panel and edits the back content and its properties, the back state must be stored independently, the front layout must remain unchanged, and neither the page height nor the canvas size may grow because of the long panel. When the user deletes content, types continuously, changes fonts, hides and restores a text layer, or rotates the model to view the other side, the text on each side must appear with its own content, color, proportions, and spatial orientation. After switching to another editing control and returning, the input and layout values for both sides must remain available for further editing.

### R8 - Layer Visibility Combinations
As the user clicks the front Logo, back Logo, front text, back text, and full-shirt texture controls at the bottom in sequence, each action must toggle only the corresponding layer's visible rendering. A disabled control must have a transparent background, while an enabled control must have a semi-transparent background in the current shirt color. After several layers are disabled in succession, the model must show only the layers that remain enabled, while their assets and geometric parameters remain saved in the session. Clicking any disabled item again must restore the asset, text, and position it had before being disabled without affecting the other switches. If the user changes an asset, adjusts the color, or rotates the view between enabling and disabling layers, each control state, the content currently visible on the model, and the targeted front or back side must continue to correspond individually; repeated operations must not create additional layers.

### R9 - Immediate Export of the Current View
If the user clicks the download control immediately after changing the shirt color, replacing a texture or Logo, adjusting Logo or text geometry, toggling layers, entering text, dragging the camera, or zooming with the mouse wheel, the application must generate a PNG from the WebGL canvas as it is already displayed at the moment of the click. The exported image's colors, front and back content, decal positions, layer combination, model shading, and camera angle must match the current on-screen frame, with no additional wait beyond the time required to load resources. When the user downloads repeatedly from different editing results, each generated image must correspond to the current state at its own click. The download action itself must not change the model, close a panel, toggle a layer, reset the camera, or allow an earlier view to overwrite a later result.

### R10 - Return and Session Persistence
When the user clicks "Go Back" at the top right in customization mode, the editing controls on the left, the open editing panel, and the layer controls at the bottom must exit; the introduction heading, description, and "Customize It" button must reappear while the 3D canvas continues rendering the current model. After the user enters customization again, the shirt color, applied image, built-in assets, front and back text, Logo geometry, layer visibility, and camera angle must all retain the session state from before leaving. Repeatedly moving back and forth must not create stacked canvases or cause one input to be handled more than once; panel switching and canvas interactions must still execute exactly once. Only refreshing the page may start a new session and restore the introduction and the defined initial customization values, and a locally selected image must not persist across a refresh.

### R11 - Viewport and Resource Lifecycle
When the page loads in a wide desktop, narrower desktop, or mobile viewport, the canvas must cover the current viewport exactly. On a wide desktop, the model must leave room for the introduction content on the left; in a narrower viewport, the model must be centered. In mobile customization mode, the editing controls must remain vertically arranged on the left, while the controls at the bottom wrap to the available width. When only five controls fit on one row, the five visibility controls must occupy the first row and the download control must be centered on the next row. A long panel must scroll only within its own area. If the user changes the viewport size during a session, the canvas size and bottom-control arrangement must update while preserving the current color, assets, text, layers, and panel scroll position. While a local image is being read, the current texture must remain in place; only after reading finishes may the target resource be committed and switched, so that empty content does not overwrite the model and a previous selection is not written to a non-target layer.
